## The arc

**Spreadsheet → script → pipeline → agent.** Four phases, the same move each time: take a process
everyone ran by hand, and rebuild it so the result can be verified instead of trusted.

**2015–2019 · Excel and VBA**
Report preparation measured in days, automated down to hours. What actually mattered from this
period wasn't the macros — it was learning where the spreadsheet stops being the right tool.

**2019–2021 · SQL**
Moved the work into SQL Server: advanced T-SQL, dimensional modeling, integrity checks that became
the team standard. Reporting accuracy stopped depending on who happened to prepare the file.

**2021–2026 · Python pipelines and RPA**
ETL over 7M+ row datasets. Automation against government portals with unstable APIs, inconsistent
responses and regional variation — systems that punish the obvious implementation. Reconciliation
across sources that never match cleanly, which is most of real-world data work.

**2026 · LLM agents**
Designed and shipped my firm's agent program: staged skills, structured outputs, and deterministic
post-validation of every extracted value against its source. Used daily by 23 people, close to half
the company, on real client data. One document-processing job that occupied two people for three
weeks now completes in under five hours.

---

## How I work

The pattern that repeats across all four phases: most engineers solve the problem the easy way, and
the easy way breaks in a constrained environment — an unstable upstream, a regulated output, a user
who can't check the result themselves.

The work is finding the version that survives contact with that constraint, and then proving that it
did. The scaffolding verifies; the model, the script and the spreadsheet don't get to be trusted on
their own.

That's the part that transfers. Tools turn over every few years. This doesn't.
